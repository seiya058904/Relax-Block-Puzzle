## 4. 已确认问题、复现与最小修复

分级：P1 表示破坏正式成绩隔离；P2 表示可达的功能、输入或生命周期故障；P3 表示较低影响的反馈/表现或交接可靠性问题。本次没有确认 P0。置信度针对列明的复现路径，不代表未执行设备平台也已实测。

### F01 · P1 · 旧有效管理员验证 + 撤销污染正式最高分

**平台与位置：** 微信可通过正常 UI 到达。`WX/game/GameState.js:1566 submitAdminCode`、`:1146 useUndoTool`；三端共同资格边界及 `S/game/ScoreManager.js:44`。

**复现与影响：** 首页提交有效管理员验证，返回尚未完成时关闭面板；开普通局并合法放置；旧成功响应返回后启用管理员；撤销普通局快照，旧代码恢复 `bestScoreEligible=true`，之后管理员放置把正式最高分从 10 写至 20。需要真正有效的认证结果，**不是服务器身份验证绕过**。Web/Android 提交是同步路径，没有宣称其正常 UI 也存在这条异步链。

**根因与修复：** 请求没有面板/局代际归属；资格被无条件从快照恢复。微信用递增验证代际，关闭、重开/新局使旧回调失效；仍有效的后台验证可正常完成。三端撤销资格取当前资格、快照资格和管理员状态的共同约束；共享计分器再拒绝管理员写分。

**验证/置信度：** 高。原始真实生成/拖放复现、独立 Red-Team 成功/失败/异常/取消/重复提交反例，`state-race-regressions.test.mjs`。管理员关闭后本局仍不合格；新普通局可以正常计分。

### F02 · P2 · 旧局最高分完成回调写错当前显示或留下陈旧首页

**平台与位置：** Web、Android 异步适配；`S/game/ScoreManager.js:44`，三端 `GameState.initializeHomeState/refreshBestScores`。微信同步存储没有同一延迟完成竞争。

**复现与影响：** normal 的保存等待锁时回首页并选 easy，旧结果曾把 easy 的显示 2 改为 normal 的 10；只丢弃旧回调又会使同难度首页继续显示 5，而存档已是 10。

**修复：** 捕获难度/局代际，过期结果不直接修改当前局纪录；保留合法历史写入，并为当前展示难度做可信重读。页面隐藏时沿既有回调门禁等待恢复绘制。

**验证/置信度：** 高。实际 Chromium 的 Web Locks、IndexedDB 两条路径均验证 persisted=10/display=10，另测不同难度隔离。[证据](../audit/concurrency/browser/results.json)

### F03 · P2 · 清分未提交即显示 0，或完成后旧缓存长期残留

**平台与位置：** Web/Android 的异步新局竞争，三端的读写失败恢复；`WEB/game/GameState.js:538/553/571` 及对应 WX/AND，`S/utils/storage.js:36`、ScoreManager。

**复现与影响：** 锁中的清分尚未提交时重开，存档最终为 0 而新局显示仍为 100；写入配额失败时存档仍 100，却曾显示清空成功。进一步反证：写入后事务拒绝、紧随其后的读取失败、下一次或已经排队的得分完成，均可能使旧 best/庆祝门槛残留。

**修复：** 清分提交后才按可信读取协调显示，失败读取保留可信缓存。待恢复的难度/代际与阈值是否已处理保存在运行时 Map，下次写入前、当前写入完成及前台恢复重试。`saved.previous` 取自锁内自身写入之前，可修复未知清分结果的阈值；显示已先变为 0 时也明确处理等值阈值。清分其他难度不会使当前局回调失效。

**验证/置信度：** 高。独立 13 项排队/错误边界 + 4 项等值反例全过；源 `reset-reconcile-regressions.test.mjs` 另含正常提交但显示提前刷新的路径。事务模拟与原生设备明确区分。未改变锁、存储键或格式。

### F04 · P3 · 其他难度事件被误认为当前局外部纪录

### F08 · P2 · 鼠标点击原生字段后默认动作夺走焦点

**平台与位置：** Web/Android shim 的 mousedown，例如 Web shim:121；微信没有浏览器鼠标默认动作。

**复现与影响：** Canvas 字段在 touch 流程可聚焦，但实际鼠标点击后 activeElement 立即变 BODY，实体键盘无法输入。

**验证/置信度：** 高。真实鼠标点字段后保持 wxKeyboard 焦点，两端资源宿主及 preventDefault 行为断言通过。

### F09 · P2 · 丢失 mouseup 后旧拖动延续到下一点击

**平台与位置：** Web 鼠标、Android JS 的外接鼠标路径；两端 shim:112 附近。微信 native touch session 原有取消语义保留。

**修复：** blur 和 buttons=0 取消鼠标所有权；mouseup 仅主按钮结束拖动。blur 只取消输入，声音与主循环继续依据真实页面可见性。

**验证/置信度：** 高（事件/实际鼠标路径）。Chromium 中的受控 blur 信号 + 真实 CDP buttons=0 移动验证；未声称物理 OS 窗口切换已实测。棋盘、得分、触摸标识与音频可见性断言均保留。

### F10 · P2 · 短视口负格子导致 Canvas 启动错误

**平台与位置：** Web 的窗口旋转/缩小可实际到达；Android/微信固定竖屏只验证相同适配器的受控短视口保护。三端 Renderer.getLayout/render、GameState.setLayout、InputManager、Main；如 `WEB/game/Renderer.js:258/349`。

**复现与影响：** Web 568×320 产生负 cellSize，`arcTo` 收到 -11 半径，抛 IndexSizeError，启动错误覆盖层隐藏 Canvas；恢复尺寸也不能解除，需要刷新。640×360 的格子也不可用。

**修复：** 实际宽<320、高<560 或可用格子<=4 时显示“请转为竖屏或增大窗口”，格子数值保持正数，清空点击区、冻结玩法/Combo/UI 动画并停帧。恢复可用尺寸后继续同一局。320×568 等正常视口原几何保持。

**验证/置信度：** 高。真实 Web、Android 资源宿主；180 ms 清线中缩小，等待 500 ms 后 remainingTime/棋盘/分数保持，恢复只结算一次至 160。还验证键盘输入在缩小及恢复间保留。原生虚拟 IME 的布局/确认体验待设备验收。[输入报告](../audit/input/BROWSER-QA-REPORT.md)

**复现与影响：** 旧 cp -r 在目标 audio 已存在时再运行，生成 audio/audio，资源验证失败且重复增大包。涉及 Android 交接镜像，微信轻量音频不受影响。
